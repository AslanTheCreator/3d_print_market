# Backend: идемпотентность заказа

Это предложение для согласования, а не действующий контракт.

Для текущего `POST /order/BOOKED` frontend нужен `Idempotency-Key` со следующими свойствами:

- область уникальности — авторизованный пользователь и ключ;
- повтор одинаковых key и payload возвращает сохранённый результат без нового заказа;
- повтор ключа с другим payload возвращает стабильную conflict-ошибку;
- заказ и результат идемпотентности сохраняются атомарно;
- параллельные одинаковые запросы создают заказ один раз;
- срок хранения и формат ошибки согласуются отдельно.

После подтверждения backend frontend должен генерировать ключ на логическую операцию и повторно использовать его при retry после сетевой ошибки.
