# Backend: идемпотентность создания заказа

Для `POST /order/BOOKED` нужно поддержать заголовок `Idempotency-Key`.

Требования:

- область уникальности: авторизованный пользователь и ключ;
- одинаковые ключ и body возвращают сохранённый результат без повторного создания заказа;
- тот же ключ с другим body возвращает `409` и код `IDEMPOTENCY_KEY_REUSED_WITH_DIFFERENT_PAYLOAD`;
- успешный response сохраняет текущий формат;
- заказ и результат запроса сохраняются атомарно;
- параллельные запросы с одним ключом создают заказ только один раз;
- срок хранения результата — не менее 24 часов.

После готовности backend frontend должен генерировать один ключ на логическую операцию создания заказа и повторно использовать его при retry после сетевой ошибки.
