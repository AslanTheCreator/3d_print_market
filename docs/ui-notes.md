# Заметки по UI

## Автообновление товаров на главной странице

Предлагаемый вариант для дальнейшей реализации; автообновление пока не добавлено.
Обновлять данные товаров без перезагрузки страницы.

### Поведение

- Через отдельный запрос TanStack Query проверять первые 18 товаров существующим
  API раз в 60 секунд, только пока главная страница открыта и вкладка видима.
- При возвращении во вкладку или восстановлении сети проверять данные, если
  последняя успешная проверка была больше минуты назад.
- Если загружена только первая порция и пользователь находится наверху,
  автоматически применять изменения. В остальных случаях показывать
  «Есть обновления — обновить», сохраняя текущую ленту и позицию прокрутки.
- По нажатию начинать ленту со свежей первой порции и соответствующего курсора;
  ранее загруженные порции сбрасывать, чтобы не смешивать разные версии выдачи.
- Во время фонового запроса сохранять товары на экране. При ошибке показывать
  небольшое уведомление с повтором, не заменяя каталог экраном ошибки.
- Не допускать конфликтов обновления с подгрузкой следующей порции.

Такой вариант актуализирует начало ленты. Для обновления цен и остатков всех
уже загруженных товаров потребуется перечитывать все порции, что увеличит нагрузку.

### Нагрузка

Сейчас главная использует бесконечную подгрузку по 18 товаров. `staleTime` в
5 минут определяет свежесть кеша, но не запускает периодическое обновление.
Стандартный refetch бесконечного списка последовательно перечитывает все
загруженные порции ([документация TanStack Query](https://tanstack.com/query/latest/docs/framework/react/guides/infinite-queries)).
Каждая порция обычно требует двух API-запросов: товары и метаданные изображений.

При полном обновлении раз в минуту:

| Загружено товаров | API-запросов в минуту на посетителя |
| --- | --- |
| 18 | около 2 |
| 90 | около 10 |
| 180 | около 20 |

Проверка только первой порции ограничивает периодическую нагрузку примерно
двумя запросами в минуту на активную вкладку независимо от глубины прокрутки.
Для 1 000 таких вкладок это около 33 дополнительных запросов в секунду.
Оценка не учитывает сами изображения, повторы, проверки при возвращении и
обычную навигацию. Нагрузка на браузер ожидается небольшой; стоимость для
backend необходимо подтвердить замерами API и числом одновременных посетителей.

### Проверки при реализации

- отсутствие дубликатов и пропусков при обновлении и последующей подгрузке;
- сохранение позиции прокрутки до применения обновлений;
- остановка опроса в скрытой вкладке и после ухода с главной;
- обновление при возвращении и восстановлении сети с учётом свежести данных;
- сохранение товаров при фоновой ошибке и успешный повтор;
- отсутствие конкурирующих запросов обновления и подгрузки.
